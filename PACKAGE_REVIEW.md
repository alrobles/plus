# Comprehensive Review of the plus R Package

## 1) Algorithm Understanding (PLUS Core)

### Methodology Implemented

The package implements an iterative **PU-learning** (Positive and
Unlabeled learning) procedure on top of penalized logistic regression
([`glmnet::cv.glmnet`](https://rdrr.io/pkg/glmnet/man/cv.glmnet.html))
with binomial family (`R/plus.R:46-53`, `DESCRIPTION:7`).

The core idea in code:

1.  **Treat known positives as fixed** (`valid.id <- which(y == 1)`) and
    others as unlabeled/invalid (`R/plus.R:27,31`).
2.  **Iteratively sample unlabeled cases** (roughly balanced to
    positives), train CV logistic model on positives + sampled unlabeled
    (`R/plus.R:39,46-53`).
3.  **Predict all rows**, derive a positive quantile cutoff from
    positive predictions (`qq`) (`R/plus.R:55-57`).
4.  **Rescale around cutoff** and squash via sigmoid
    (`1/(1+exp(-10*...))`) (`R/plus.R:60-64`).
5.  **Update pseudo-label probabilities** and stochastically relabel
    sampled unlabeled via Bernoulli draws (`rbinom`) (`R/plus.R:69-74`).
6.  **Stop** when sampling weights depleted or label changes stabilize
    (`R/plus.R:76-88`).
7.  **Fit final CV logistic model** on full relabeled data and store
    outputs in class `plus` (`R/plus.R:92-105`, `R/new_plus.R:29-36`).

### Mathematical / Statistical Foundations Visible in Code

- **Penalized logistic regression** with elastic-net mixing `alpha`
  (`R/plus.R:48`).
- **PU relabeling loop** with stochastic EM-like updates (probability
  update + Bernoulli sampling) (`R/plus.R:69-74`).
- **Thresholding by positive quantile** (`qq`) for calibration to
  known-positive score distribution (`R/plus.R:57`).
- **AUC metric support** via concordance
  ([`survival::concordance`](https://rdrr.io/pkg/survival/man/concordance.html))
  (`R/auc.R:21-22`).

### Data Flow Through Package API

- **Fit**: `plus(x, y)` → returns S3 class `"plus"` with:
  - `$plus` (`cv.glmnet` object),
  - `$pred_y`, `$cutoff`, `$predicted_coefficients`, `$call`
    (`R/new_plus.R:30-35`, `R/validate_plus.R:18-21`).
- **Predict**:
  [`predict.plus()`](https://alrobles.github.io/plus/reference/predict.plus.md)
  gives response/class (`R/predict.plus.R:34-55`).
- **Evaluate**:
  [`assess.plus()`](https://alrobles.github.io/plus/reference/assess.md),
  [`get_auc.plus()`](https://alrobles.github.io/plus/reference/get_auc.md),
  [`get_predictions()`](https://alrobles.github.io/plus/reference/get_predictions.md)
  (`R/assess.plus.R:30-57`, `R/get_auc.R:29-41`,
  `R/get_predictions.R:27-49`).

## 3) Enhancement Opportunities

### High-Priority Correctness / API Issues

1.  **`predict.plus` docs vs implementation mismatch** Docs claim
    support for `link`, `coefficients`, `nonzero`, etc., but
    implementation only handles `response` and `class`
    (`R/predict.plus.R:15-20`, `R/predict.plus.R:50-55`).

2.  **`s = "lambda.1se"` likely broken** `match.arg(s)` has no explicit
    choices; formal default only includes `"lambda.min"`
    (`R/predict.plus.R:34,38`).

3.  **AUC helper logic is questionable**
    [`auc_matrix()`](https://alrobles.github.io/plus/reference/auc_matrix.md)
    reconstructs labels as balanced `0/1` ignoring actual rowwise class
    content in `y` (`R/auc_matrix.R:22-24`).

4.  **Evaluation utility name suggests CV but uses 1 fold**
    `foldid = rep(1, nrowy)` so no actual fold split in
    [`plus_cv_lognet()`](https://alrobles.github.io/plus/reference/plus_cv_lognet.md)
    (`R/plus_cv_lognet.R:33,45`).

### Quality / Documentation Gaps

- **No tests**; no vignettes (none found via directory scan).
- **Numerous typos** and doc issues (e.g., “pluse”, “consturctor”,
  “retrived”) in Rd/R docs (e.g. `man/predict.plus.Rd:13`,
  `man/fit_plus_example.Rd:6`).
- **README has malformed heading escape** (`\## Example`)
  (`README.md:32`).
- **Pkgdown site appears stale** at version 0.0.1 while DESCRIPTION is
  1.0.0 (`docs/index.html:36`, `DESCRIPTION:3`).

### Performance / Design Opportunities

- Main loop can run up to **10,000 iterations** with repeated
  `cv.glmnet` fits (heavy) (`R/plus.R:37,46`).
- **No exposed controls** for `max_iter`, `nfolds`,
  seed/reproducibility, convergence diagnostics.
- **Missing S3 methods**: No `summary.plus`, `plot.plus`,
  confusion-matrix utility, calibration curves.
- **Limited input validation** in
  [`plus()`](https://alrobles.github.io/plus/reference/plus.md) (binary
  checks, NA handling, shape checks not explicit).

## 4) Best Usage Patterns

### Current Intended Use

- Intended for **binary PU contexts** with known positives and unlabeled
  negatives; especially unbalanced/sparse settings (`README.Rmd:31-43`,
  `R/plus.R:27-33`).
- Practical flow:
  1.  `fit <- plus(x_train, y_train)` (`README.Rmd:67`)
  2.  `predict(fit, newx=...)` (`README.Rmd:68`)
  3.  `get_auc(...)` / `assess(...)` (`README.Rmd:86,90`)
- **Text-mining framing** is suggested by included abstract datasets
  (`lacs`, `lacsSample`) and DESCRIPTION statement on text analysis
  helpers (`DESCRIPTION:8`, `R/lacs.R:1-4`).

### User-Friendliness Improvements

- Add formula interface.
- Stronger checks/errors.
- Explicit class labels semantics.
- Robust predict types.
- Reproducibility controls (seed parameter).
